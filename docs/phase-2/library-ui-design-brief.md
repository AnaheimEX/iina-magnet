# iina-magnet 媒体库 UI 设计需求（交付 Claude design）

> 目的：为 **媒体库总览页（Library Browser）** 与 **作品档案页（Title Detail）** 产出视觉设计。本文是给设计工具的需求说明，描述内容、布局、状态与交互，不含最终视觉细节——配色/字体/间距由设计自由发挥，但需遵守下方约束。
>
> 产品背景：iina-magnet 是 **macOS 桌面播放器**（iina 的 fork），新增"订阅→下载→边看边播→媒体库"。本设计是其中"媒体库"功能区的两个独立窗口页面。主用户场景是**中文用户的番剧/影视收藏**（资源来自 mikanani 等）。参考体感：Infuse / Plex / Apple TV app 的"海报墙 + 档案页"，但要 **macOS 原生质感**（不是网页风、不是移动端）。

---

## 0. 全局约束

- **平台**：macOS 桌面 app，窗口化、可缩放。深色/浅色两套（跟随系统）。原生控件质感（SF 字体、原生 sidebar/toolbar、vibrancy/材质背景）。
- **语言**：界面文案 **简体中文优先**，需同时给出英文版（zh-Hans / en 双语，String Catalog）。作品标题本身按数据多语言展示（见数据字典）。
- **窗口尺寸**：默认约 **1100×720**，最小约 **900×560**；布局需在该范围自适应。
- **图片**：海报/背景图是**远程 URL**（可能加载慢或缺失）。所有图片位都必须设计 **占位态 + 加载态 + 失败兜底**（用作品标题首字/通用海报占位）。不要假设每集都有缩略图（Bangumi 常无分集图）。
- **可访问性**：支持键盘导航、VoiceOver 标签、动态字体；色彩对比达 WCAG AA。
- **不在本次范围**：设置页、订阅管理页、BT 下载页（已有）；这两页只管"浏览已入库内容 + 打开档案 + 发起播放"。

---

## 1. 数据字典（设计应基于真实字段）

页面展示的数据来自这些模型字段（已实现）。设计时按"字段可能为空"处理。

**作品 Title**
- `titleZh` 中文标题（主显），`titleJa` 日文原名、`titleEn` 英文名（次显，可能空）
- `kind` 类型：剧集/番剧 `tv`、电影 `movie`、未识别 `unknown`
- `overview` 简介（中文优先，可能较长）
- `posterURL` 竖版海报、`backdropURL` 横版背景图（电影/部分剧有；番剧可能只有海报）
- `releaseYear` 年份
- `tmdbRating` / `doubanRating` 评分（0–10，可能只有其一或都无；**并列展示，标明来源**）
- `aggregateState` 三态：未看 `unseen` / 在看 `inProgress` / 已看 `completed`
- `matchState` 匹配状态：已确认 `confirmed` / 待确认 `pendingConfirmation` / 未匹配 `unmatched`
- `tags` 标签集合，每个标签有分类：类型(genre)/年份(year)/地区(country)/评分档(ratingBucket)/清晰度(quality)/字幕组(releaseGroup)/自定义(userDefined)

**季 Season** → `number`（电影为占位 0，UI 隐藏）
**集 Episode** → `number` 集号、`title` 集标题（可能空）、`overview`、`airDate` 播出日期、`watchState`（未看/在看/已看）、`progress`（0–1，续播位置）
**版本文件 VersionFile**（同一集可有多个）→ `resolution` 清晰度(如 1080p/2160p)、`releaseGroup` 字幕组、`fileSizeBytes` 大小、`languages` 字幕语言、`isMissing` 文件是否已丢失

## 2. 页面 A：媒体库总览（Library Browser）

### 2.1 目标
让用户**一眼扫过整个收藏**、快速筛选、点进某部作品。海报墙为主。

### 2.2 区域结构
1. **顶部工具栏**：
   - 视图切换：网格(海报墙) / 列表 两种（图标切换）
   - 搜索框：按中/日/英标题模糊搜索，实时过滤
   - 排序：最近更新 / 标题 / 年份 / 评分
   - "扫描"按钮（触发重新扫描，带进度，见 2.6）
2. **左侧筛选 Sidebar**（可折叠）：
   - 三态：全部 / 未看 / 在看 / 已看（各带计数）
   - 类型：番剧 / 剧集 / 电影 / 未识别
   - 标签分组：按 genre/年份/地区/字幕组 折叠列出，可多选
   - "待确认"入口（matchState 非 confirmed 的数量，醒目角标）
3. **主内容区**：海报墙网格 或 列表
4. **底部统计条**（固定）：番剧 N · 电影 N · 未识别 N · 合计 N；**点击某项跳到对应筛选**

### 2.3 海报卡（网格项）
- 竖版海报为主体（约 2:3）
- 海报上/下叠加：`titleZh`（1–2 行截断）、`releaseYear`
- **三态角标**：未看/在看/已看用清晰可辨的标记（如已看打勾、在看显示进度条/百分比、未看无标记或弱标记）
- **类型角标**：番剧/电影/剧集小标（番剧与电影要能一眼区分）
- **待确认角标**：matchState≠confirmed 时显示醒目标记（提示"需确认"）
- hover：轻微放大/高亮 + 显示快捷操作（播放最近一集 / 打开档案）
- 海报缺失：用"标题首字 + 类型色块"占位

### 2.4 列表行（列表视图）
列：海报缩略 | 标题(中/原文) | 类型 | 年份 | 季·集数 | 三态 | 评分 | 更新时间

### 2.5 空 / 加载 / 错误态
- **空库（未配置扫描目录）**：引导插画 + "去设置添加扫描目录" CTA
- **空库（已配置、未扫描）**：提示 + "开始扫描" CTA
- **筛选无结果**：友好空状态
- **海报懒加载**：骨架/模糊占位 → 淡入
- **错误 banner**（顶部，可关闭）：如"扫描出错 / 元数据源限流"，带"查看日志"

### 2.6 扫描进度
触发扫描时：顶部或底部出现**进度条**（已扫 X / 共 Y + 当前文件名）+ 取消按钮；增量扫描时给轻量提示（不打断浏览）。

### 2.7 交互
- 单击卡片 → 打开档案页（页面 B）
- 右键菜单：打开档案 / 播放最近一集 / 在 Finder 中显示 / 重新匹配 / 刷新元数据
- 键盘：方向键在网格移动、回车打开、`/` 聚焦搜索

## 3. 页面 B：作品档案页（Title Detail）

### 3.1 目标
一部作品的"门面页"：海报+背景+元信息+演职员+集数网格，并能**直接发起播放**。

### 3.2 区域结构（从上到下）
1. **Hero 头图区**：
   - `backdropURL` 横向背景图铺满顶部，底部渐变过渡（无背景图时用海报模糊放大或纯色）
   - 叠放：竖版 `posterURL` 海报、`titleZh`（主，大号）、`titleJa`/`titleEn`（次，小号灰字）
   - 元信息行：年份 · 类型 · 季数/集数 · 评分（**TMDB x.x / 豆瓣 x.x 并列且标来源**）
   - `tags` chips（genre/年份/地区等，不同分类可弱区分）
   - **主操作按钮**：电影=「播放」；剧集/番剧=「继续观看 第N集」（无进度时为「从第1集开始」）
2. **匹配状态 banner**（仅当 matchState≠confirmed）：醒目条——"自动匹配不确定，点此从候选中确认"，带「确认匹配」按钮
3. **简介区**：`overview`，过长可"展开/收起"
4. **演职员区**（有数据时）：横向滚动，头像+姓名+角色（声优）；无数据则隐藏
5. **集数区**（仅 tv/番剧；电影隐藏）：
   - **季切换器**（多季时）：Tab 或下拉
   - **集数网格**：每个集卡显示 集号、`title`（可空）、**三态/进度角标**、`airDate`（可选）
   - 集卡点击 → 播放该集
6. **版本与文件区**：当选中集有多个 `VersionFile`：
   - **版本切换器**：列出各版本（清晰度 / 字幕组 / 大小 / 字幕语言），默认选最高清晰度
   - 每个版本：「播放」、「在 Finder 中显示」
   - `isMissing` 的版本：置灰 + "文件已移动/删除"标记，不可播

### 3.3 状态
- **未匹配作品（unknown）**：无元数据时，仅展示文件名推断的标题 + 文件列表 + 「手动匹配」CTA；不显示空的海报/简介骨架
- **海报/背景缺失**：占位（同总览）
- **集标题缺失**：只显示"第 N 集"
- **加载中**：头图与海报骨架

### 3.4 交互
- 集级进度**跨版本共享**：看过 720p 第 3 集，切到 1080p 仍显示已看（设计上集卡的三态只跟"集"走，不跟版本走）
- 「继续观看」跳到 `aggregateState`/各集进度推断的下一集
- 右上角操作：刷新元数据 / 重新匹配 / 在 Finder 中显示
